# HI5 Portal — Python AI Service (scikit-learn + FastAPI)

The **AI at-risk model** for the defense demo. A standalone Python microservice
that trains a **scikit-learn Linear Regression** on the school's historical
quarterly grades and returns risk classifications. The Node.js backend calls it
only when `AI_PROVIDER=python` is set — the default `node` provider keeps the
built-in regression, so **nothing breaks if the Python service isn't running**.

## Architecture

```
Teacher / Registrar / Principal UI
        │  GET /api/at-risk/trends
        ▼
Node.js backend (Express) ── AI_PROVIDER? ──┐
        │  (default: node)                    │  AI_PROVIDER=python
        ▼                                     ▼
  classifyStudent()                     FastAPI service (Python)
  (built-in regression)                 POST /predict  → risk classification
                                         GET /model    → training metrics
```

- **Node.js** → web app, auth, database, and the default classification.
- **Python** → machine learning. Trains the baseline model, predicts per-student
  risk. Switched on with one config flag — a microservice pattern.

The Python classifier uses the **exact same thresholds** as the Node.js one
(`PASSING=75`, `MONITOR=80`, slope ±1), so both providers return identical
labels and the rest of the system is unchanged.

## Setup (Windows)

```bash
cd ai-service
pip install -r requirements.txt

# 1) Train on the school's real grades (reads server/.env for DB access)
python train.py
# → [OK] Trained on N quarterly-average rows  (R², MAE printed)

# 2) Start the service
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

Quick check: open http://127.0.0.1:8000/health and http://127.0.0.1:8000/model
(`R²`, `MAE`, sample count — great for a panelist question).

## Switching the backend to use Python

In `server/.env`:

```
AI_PROVIDER=python          # default is node
AI_SERVICE_URL=http://127.0.0.1:8000
```

Set `AI_PROVIDER=node` (or leave it unset) to go back to the built-in
regression. If Python is the provider but the service is down, the backend
automatically falls back to the local regression — no errors reach the UI.

## Endpoints

| Method | Path       | Purpose                                             |
|--------|------------|-----------------------------------------------------|
| GET    | `/health`  | Liveness + whether the model is trained             |
| GET    | `/model`   | Training metrics (samples, R², MAE, slope)          |
| POST   | `/predict` | `{ student_id, quarters: [q1..q4] }` → risk result  |
| POST   | `/train`   | Re-train from `data/grades.csv`                     |

## Defense talking points

> "The AI component is a Python-based machine learning service built with
> scikit-learn. We trained a Linear Regression model using historical quarterly
> grades (Q1–Q4). Once trained, the model is saved and loaded by a FastAPI
> server. Whenever the Node.js application needs a prediction, it sends the
> student's grades to the AI service. The model projects the expected final
> grade, which is converted into a risk score and classification for the
> registrar and teachers."

> "Node.js handles the web application, authentication, and database
> operations, while Python handles machine learning. This follows a
> microservice architecture, making the AI component modular, maintainable,
> and easier to upgrade or replace with more advanced models in the future."

And if they ask about the flag: the config switch exists so the demo can run
with or without the Python service installed — the built-in Node.js regression
is the fallback that keeps the school working.

## Files

- `model.py` — the regression + classification logic (mirrors the Node model)
- `main.py` — FastAPI app
- `train.py` — exports real grades from MySQL → `data/grades.csv`, trains & saves
- `data/grades.csv` — generated by `train.py` (git-ignored)
- `saved/model.joblib` + `saved/metrics.json` — generated (git-ignored)
